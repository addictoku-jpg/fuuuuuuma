# 【ClaudeCode】知らないと損する神機能

> Claude Codeをただのチャット相手として使っていませんか。この資料は3つの疑問に順番に答えていく形で構成しています。①そもそも「スキル」って何なのか、②それが分かった上でClaude Code全体は結局何をしてくれるツールなのか、③実際に今日から何を入れて、どう探せばいいのか。この順番で読めば、Claude Codeという1つの道具を初心者でも一気通貫で理解できます。

## TL;DR（3行）

- Claude Codeの「Skill」は、GPTsやGemsのような指示書だけの仕組みとは根本的に違います。指示書に加えて実行可能なプログラムとフォルダ構成を持っていて、毎回同じ処理を安定して繰り返せます。
- Claude Code全体は「バラバラな9つの便利機能」ではなく、土台となる3つの動かし方（型を持ち込む・自分の知見を移植する・外部と繋ぐ）と、そこから働き方を広げる拡張機能という2階建てで理解すると一気に見通しがよくなります。
- 何かを探す前に、まず自分の業務に合わせたオリジナルのスキルを作ることが一番価値があります。それでも他の人の知見を借りたいときのために、信頼できる探し方（Claude Code Marketplace／skills.sh／Xでのリアルな評判検索）も紹介します。

## 1. 疑問①：スキルって結局何なのか

「スキル、スキルってよく聞くけど、結局GPTsやGemsと何が違うの」という疑問を持っている人は多いはずです。ここが分かっていないと、この先どれだけ機能を紹介されても「へえ、すごいね」で終わってしまいます。なので遠回りに見えても、まずここから始めます。

### GPTsとGemsは「指示書」だけ

ChatGPTのGPTsとGeminiのGemは、基本的に同じものです。特定の専門家AIチャットを事前に作っておける仕組みで、中身は「指示（カスタム指示）」というテキストの指示書と、「知識」という参考ファイルの2つだけでできています。ユーザーが何か頼むと、AIはその指示書を読み込んでから回答します。つまり中身はどこまでいってもプロンプトです。プログラムを実行する手足は持っていません。

### プロジェクト機能は「指示書＋フォルダ管理」

ChatGPTにはプロジェクト機能もあります。これはGPTsと何が違うのかというと、実はベースはほぼ同じです。指示書と参考ファイルという土台は変わらず、そこに「フォルダ管理」が加わっただけです。プロジェクトという1つのフォルダの中に、チャット履歴と参考ファイルがまとまり、そのプロジェクト単位でメモリー（記憶）も蓄積されていきます。ちなみにこのプロジェクト機能を持っているのはChatGPTだけで、Geminiにはプロジェクト機能はなく、Claudeには逆にGPTsやGemのようなカスタムAIチャットの仕組み自体がありません（Claudeは最初からプロジェクト相当のフォルダ管理だけを持っている形です）。

### Skillsは「指示書＋実行できるプログラム＋ファイルシステム」

ここが決定的に違うところです。Claude CodeのSkillは、指示書（`SKILL.md`）に加えて、実際に実行されるプログラム（PythonファイルやJavaScriptファイルなど）を持てます。たとえるなら、GPTsやGemsが「キャンプの楽しみ方ガイド」だけを渡してくるのに対して、Skillは「ガイド＋すでに組み立て済みのキャンプ道具一式」を渡してくれるイメージです。

これによって何が変わるのか。一番大きいのは「同じインプットなら同じアウトプットが出やすくなる」という安定性です。GPTsの指示書にコードをそのまま貼り付ければ同じことができるのでは、と思う人もいますが、それは違います。指示書に書かれたコードは、あくまで「参考として読み込まれるプロンプトの一部」でしかなく、そのまま実行されるわけではありません。実行するかどうかも、実際にどう実行するかも、そのつど新しく生成し直す必要があります。生成には毎回ブレが生じます。一方Skillのプログラムは固定された処理なので、同じ入力に対して同じ出力を返しやすくなります。

Skillのもう1つの特徴は、1つのフォルダの中に情報を構造化して格納できることです。中心となる`SKILL.md`（指示書の本体）に加えて、`scripts/`（実行されるプログラム）、`reference/`（参考資料）、`assets/`（画像やテンプレートなどの補助ファイル）といったサブフォルダに情報を整理して詰め込めます。`SKILL.md`は長くなりすぎると読み込みに時間がかかり指示に忠実に従いにくくなるため、本体は簡潔にまとめ、細かい手順は別ファイルに逃がすのがコツです。Claude Codeは最初に各スキルの「説明文（description）」だけを読み込んでおき、実際に必要になったタイミングでスキル本体を読み込みます。これによって、使っていないスキルの情報でコンテキスト（AIが一度に扱える情報量）を無駄に消費せずに済みます。

そしてSkillは、生成して終わりではなく、生成したものを外部サービスに繋いでいくところまでをワークフロー化できます。たとえば「文字起こしを読み込んで議事録を作り、そのままNotionのデータベースに追加し、内容を理解して担当者ごとにタスクを割り振る」という一連の流れも、Skillなら1つの処理として組み込めます。GPTsやGemsは基本的に「聞いて、答える」までで完結しますが、Skillは「聞いて、処理して、外部に反映する」ところまで踏み込めるのが本質的な違いです。

なお、この仕組みを使えるのは今のところClaude Code、Codex、Cursor、Antigravityといったコーディングエージェント側が中心で、ChatGPTやGeminiのチャットアプリ上では使えません。チャットアプリの中でスキルを扱えるのは、現状ではClaudeがほぼ唯一です。

### なぜスキルがここまで注目されているのか

理由は大きく3つに整理できます。1つ目は、今説明した**品質の安定性**です。プログラムという固定された処理があることで、毎回ゼロから生成し直すGPTs方式より結果がブレにくくなります。2つ目は、**成果物のサイクルが回る**ことです。Skillを実行すると成果物（PowerPointやHTML、Excelなど）がアウトプット用のフォルダに溜まっていきます。指示書に「アウトプットフォルダの中の良い成果物を参考にしてから始める」と書いておけば、次に同じスキルを使うときに、過去の良い成果物を参考にした状態でスタートできます。良いアウトプットが良いアウトプットを呼ぶ好循環が生まれ、使うほどにスキルが育っていきます。3つ目は、**専門家の知見をそのまま移植できる**ことです。開発が得意な人が作れば開発特化のSkillになり、デザインが得意な人が作ればデザイン特化のSkillになります。他の人が作ったSkillのフォルダの中身を覗けば、その専門家がどういう手順で仕事を進めているのかを覗き見ることもできます（この点は3章で具体例とともに詳しく紹介します）。

裏を返すと、今なおGPTsやGemを一生懸命作って配っている状態は、この視点で見るとやや時代遅れです。もちろんGPTsやGemにも「手軽さ」という良さは残っていますが、繰り返し使う業務・安定した品質が欲しい業務ほど、Skill化する価値は大きくなります。

スキルの正体が分かったところで、次はいよいよ本題です。この「指示書＋実行プログラム」という仕組みを土台に、Claude Code全体が実際に何をしてくれるツールなのかを見ていきます。

## 2. 疑問②：Claude Code全体は何をしてくれるのか

Claude Codeは、最初に登場したときは「コードを生成してくれるエージェント」という開発ツールの色が強いものでした。ですが今のClaude Codeは、それだけにとどまりません。Webアプリを作る・ツールを作るという狭い用途だけでなく、自社のオペレーションを自動化したり、決まったワークフローを勝手にこなしてもらったりと、**自分専用のAIチームを作るための土台**という性格が強くなっています。

機能が多いぶん、「結局何から触ればいいのか」で迷いがちです。ここでは、Claude Codeが持つ機能を**土台となる3つの動かし方**と、**そこから働き方を広げる拡張機能**という2階建てで整理します。この分け方自体が、実際にClaude Codeを使い込んでいる人たちが最初に手を伸ばす順番と一致しています。

### 2-1. 土台となる3つの動かし方

Claude Codeを使いこなす上で、まず押さえるべきはこの3つです。逆に言うと、この3つさえ分かっていれば、あとの拡張機能はすべて「この3つのどれかを、もっと便利にするもの」として理解できます。

**① 型を持ち込む（Superpowers）**

Superpowersは、ベテランエンジニアの開発ワークフローをそのまま組み込めるプラグインです。テスト駆動開発（TDD）のRED-GREEN-REFACTORサイクルを徹底させたり、要件がふわっとしている段階から「ブレインストーミング」スキルで質問を重ねながら要件を固めてくれたりします。開発経験がなくても、経験豊富なエンジニアに壁打ちしてもらいながら計画・実行・レビューまで進められるのが最大の魅力です。ターミナル上のClaude Codeで`/plugin marketplace add obra/superpowers-marketplace`のあとに`/plugin install superpowers@superpowers-marketplace`を実行すればすぐに使えます。何もカスタマイズしていないClaude Codeは「賢いけれど型を持たない新人」のような状態なので、まずこの型を持ち込むところから始めるのが近道です。

**② 自分の知見を移植する（スキルの自作）**

1章で説明した「指示書＋実行プログラム」という仕組みを、他人が作ったものを探すのではなく、自分の業務に合わせて自分で作ってしまうという発想です。特定のバグ調査の手順、記事作成の型、問い合わせ対応のテンプレート、LP作成の流れなど、自分がいつもやっている作業を言語化して`SKILL.md`に落とし込めば、それだけで再現性の高いAI社員が1人増えるようなものです。汎用的なスキルを探すよりも、自分の業務にぴったり合った専用のスキルを自作するほうが、実は価値は大きいという考え方です。

**③ 外部と繋ぐ（MCP）**

MCP（Model Context Protocol）は、AIと外部サービスを繋ぐための共通規格です。USBの規格が定まっているおかげでいろいろな機器が同じ端子で繋がるのと同じ発想で、Slack・Notion・Googleカレンダー・Gmailといった外部サービスをClaude Codeから操作できるようになります。すでに数多くのサービスがMCPを提供しているので、自分が使っているツールに対応するMCPがあれば、読み込んで設定するだけで連携が始まります。慣れてきたら、1つのMCPサーバーを丸ごと入れるのではなく、必要な機能（下書き作成だけなど）に絞って組み込むと、AIが読み込む情報量を無駄に増やさずに済みます。

型（Superpowers）・自分の知見（自作スキル）・外部との接続（MCP）——この3つが揃うと、Claude Codeは「言われたことに答えるだけの存在」から「型を持ち、自分の知見を蓄え、外の世界と繋がって動ける存在」に変わります。ここから先の拡張機能は、すべてこの土台をどう広げるかという話になります。

### 2-2. そこから働き方を広げる拡張機能

土台の3つができた上で、Claude Codeは「どう任せる範囲を広げるか」「どう仕上げの質を上げるか」「どこから使えるようにするか」という3つの方向にさらに機能を広げています。

**任せる範囲を広げる：Auto Mode／Routines／Agent Teams**

Claude Codeには「許可を確認」「編集を承認」「プランモード」「自動モード」「許可をバイパス」という複数の実行モードがあります。初心者ほど、いちいち確認するのが面倒で「許可をバイパス」を選びがちですが、これは危険なコマンドまで無条件で実行してしまうモードで、フォルダを丸ごと削除するような操作すら確認なしに通ってしまう可能性があります。**Auto Mode**はその中間にある選択肢で、安全に実行できる操作はClaudeが自分で判断して進め、リスクがある操作だけを人間に戻してくれます。

任せる範囲を時間軸に広げたのが**Routines**です。決まった作業をクラウド上で定期的に自動実行するための機能で、たとえば「問い合わせが来たら返信文の下書きを作る」「書類選考の通過者にフォローメッセージを送る」といった業務を、毎朝決まった時間に自動でこなしてもらうことができます（デスクトップアプリの「ローカル」表示は実体が別機能の「デスクトップ スケジュールタスク」なので、パソコンの電源を切っても動き続けてほしい場合はクラウド側のRoutinesを選ぶ必要があります）。

任せる範囲を人数に広げたのが**Agent Teams**です。普段Claude Codeに何かを頼むときは、1つのセッションに対して1つの依頼をするのが基本ですが、Agent Teamsを使うと、セキュリティをチェックする担当、パフォーマンスをチェックする担当、テストをする担当というように、役割ごとに複数のエージェントからなる「チーム」を編成できます。それぞれが独立したコンテキストを持ちながら作業し、必要に応じて互いにやり取りするため、1つの巨大な依頼をチームで分担して進めるようなイメージに近くなります。似た機能にサブエージェントもありますが、こちらは複数のチームメイトが対等にやり取りしながら進める点が異なります。

**仕上げの質を上げる：Ultra Review／デザイン連携ツール**

自分の知見を移植したスキルで開発を進めた先、公開する前の最終チェックを担うのが**Ultra Review**です。GitHub連携のリモートサンドボックス上で複数のレビューをクラウド上で並列実行し、通常のレビューより深くバグを洗い出してくれます。追加コストが発生する有料の仕組みではありますが、実際にサービスをリリースする前の最終チェックとして使う価値は十分にあります。

デザイン面での仕上げを担うのが**Pencil**や、Claudeのサブスクリプションに含まれる**Claude Design**といった連携ツールです。Claude Code単体でデザインを仕上げるより、こうした専用ツールと組み合わせたほうが、AI感のあるデザインから抜け出しやすくなります（具体的なスキルとしてのImpeccableの使い方は3章で紹介します）。

**どこから使えるようにするか：Remote Control**

パソコンでClaude Codeをターミナルで起動しておいたまま、外出先でスマホから残りの指示を出せるのが**Remote Control**です。パソコンを開いたまま外に出て、スマホでリモートコントロールを使えば、AIの作業を待つだけの時間をなくせます。似た遠隔操作の仕組みは他のAIコーディングツールにも登場してきていますが、ターミナルで動かしている作業をそのままスマホに持ち出せる手軽さは、日常的に恩恵を感じやすい機能です。

以上が、Claude Codeという1つの道具の全体像です。土台の3つ（型・自作スキル・MCP）を押さえた上で、任せる範囲・仕上げの質・使える場所という3方向に機能が広がっている、という構造で捉えると、機能が多くても迷わずに済みます。研究プレビュー段階の機能を多く含むため、料金や仕様が変わる可能性がある点は留意してください。

## 3. 疑問③：今日から何を入れて、どう探すか

全体像が見えたところで、最後に「実際に何を手に取ればいいのか」を具体的に見ていきます。ここで紹介する4つのスキルは、2章で説明した土台や拡張機能を、実際にインストールできる形にしたものです。

### まず、土台の①で紹介したSuperpowersが最有力候補

2章で紹介したSuperpowersは、実は現時点でもっとも定番のインストール先の1つです。改めて役割を整理すると、ベテランエンジニアの開発の型を持ち込むプラグインで、ブレインストーミングで要件を固め、計画を立て、実行し、レビューするという一連の流れを、開発経験がない人でも自然になぞれるようになります。開発をしたい人には、まずここから触ってみることをおすすめします。

### 環境ごと整えたい人向け：Everything Claude Code（ECC）

Anthropicが開催したハッカソンで優勝した人が、10ヶ月間ひたすらClaude Codeを使い込んで蓄積したベストプラクティスを公開したものです。エージェント・スキル・コマンド・フックといった、Claude Codeが動くための環境を丸ごと装備してくれます。ただし、これは最初から入れることはおすすめしません。中身には多数のエージェントやスキル、コマンドが詰め込まれているため、Claude Codeの動き方やフォルダ構成をまだ理解していない段階で導入すると、「何が悪さをしているのか」を切り分けられなくなってしまいます。2章の内容が体に馴染んでから使うことをおすすめします。

### デザインの仕上げを任せたい人向け：Impeccable

2章で触れたデザイン連携の具体例です。AIが作りがちな「よくあるグラデーション」「量産型に見えるデザイン」を避けるためのデザインスキルで、デザインに特化した複数の小さなスキルを束ねたものになっています。`/impeccable init`のような最初のセットアップから始まり、既存のデザインを磨き上げるためのコマンド群（改善点を洗い出す`/critique`など）まで一通り揃っています。実際に構成案を投げてみると、AIっぽさが薄れた仕上がりになりやすく、デザインのフィードバックをした経験がない人ほど恩恵を感じやすいスキルです。

### スキル探しそのものを効率化したい人向け：Find Skills

ここまでの3つが「特定の業務を助けるスキル」だったのに対し、Find Skillsは毛色が異なり、**スキルを探す・管理するためのスキル**です。Vercel Labsが提供する`skills.sh`というスキルのエコシステムを土台にしており、コマンドラインから`npx skills add`のような形でスキルを直接検索・追加できます。ターミナル操作に慣れていない人にとってはハードルがあるかもしれませんが、インストール数が非常に多い実績のあるスキルなので、選択肢の1つとして知っておく価値はあります。

### 良いスキルの安全な探し方

Find Skillsのように専用のツールを使わなくても、良いスキルを探す方法は大きく3つあります。1つ目は**Claude Code Marketplaces**のような、コミュニティ主導の第三者ディレクトリです。数千件規模のスキルやプラグイン、MCPサーバーが並んでいて、インストール数順やスター順で探せます。ただしここはあくまで第三者・コミュニティの立ち位置であることを踏まえておく必要があります。誰でも公開できる場所である以上、中には脆弱性のあるものや、セキュリティ的に望ましくないプロンプトが含まれているものが紛れ込んでいる可能性はゼロではありません。

2つ目は、Vercelが運営する**skills.sh**です。上位に並んでいるスキルの多くが、Vercel自身やAnthropic公式、Microsoftなど、実際にそのサービスを提供している企業自身が公開しているものである点が特徴です。第三者コミュニティのマーケットプレイスと比べて、どこの誰が作ったものかが分かりやすく、信頼性の面で安心しやすい選び方です。

3つ目は、**Xでのリアルな評判を検索する**という探し方です。インストール数のような定量的な指標だけでなく、実際に特定の業務でそのスキルを使ったユーザーの生の声を確認したいときは、Grokのようにリアルタイムの投稿を検索できるAIで「このスキルを使っている人の感想」を集めてくるのが有効です。数字だけでは見えない「実用的かどうか」の温度感を掴みやすくなります。

どの探し方を使うにしても共通して言えるのは、**インストール数が多く、公式や有名な企業が出しているものほど安心して使いやすい**ということです。逆に、聞いたことのない個人名義のスキルを深く調べずに入れるのは避けたほうが無難です。そして何より、2章・3章を通して見てきたように、**探す前にまず自分の業務に合わせたオリジナルのスキルを作ることが、実は一番価値が大きい**という点は忘れないでください。

## 4. 今日からの使い方（初心者基準）

3つの疑問への答えが出そろったところで、「結局何からやればいいの」という人向けに、悩みベースの対応表をまとめます。

| こんな悩み | こう頼むだけ |
|---|---|
| 何から手をつければいいか分からない開発をしたい | Superpowersを導入して、作りたいものをそのまま伝えてブレインストーミングから始める |
| 毎回同じような許可確認でテンポが悪い | 実行モードをAuto Modeに切り替えて、安全な操作は任せてしまう |
| SlackやNotion、Gmailと連携して自動化したい | 使っているサービスのMCPを探してインストールし、Claude Codeから操作する |
| 決まった時間に決まった作業を繰り返したい | Routinesで、繰り返している業務を1つ定期実行に登録する |
| 作ったデザインがどこかAIっぽくなってしまう | Impeccableを入れて、`/impeccable init`から始めてみる |
| 良いスキルを探しているけど何が安全か分からない | まずskills.shで公式が出しているものを確認し、気になったらXで評判も検索する |

たとえばSuperpowersを試すときは、難しいコマンドを覚える必要はありません。「今、こういうことをやりたい」という悩みをそのまま自然な言葉でClaude Codeに伝えるだけで、あとはブレインストーミングのスキルが質問を重ねながら要件を一緒に固めてくれます。専門用語を先に覚えてから使う必要はなく、まず触ってみることが一番の近道です。

## 5. もう一歩進んだ使い方

ここからは少し踏み込んだ内容です。2章・3章で触れた「自分の知見を移植する」を、自分で実践する段階に進んだ人向けに、実際のフォルダ構成の考え方を紹介します。

1つのスキルフォルダは、次のように役割ごとに分けて整理できます。

- `SKILL.md` — 中心となる指示書。ここは簡潔に、全体の流れだけを書く（目安は200行以内）
- `scripts/` — 実際に実行されるプログラム（`.py`や`.js`など）
- `reference/` — 参考にしたい資料やデザインのトンマナなど、判断材料になる情報
- `assets/` — 出力結果を確認するためのビューアーなど、補助的なファイル

指示書をすべて`SKILL.md`に詰め込もうとすると、長くなりすぎて逆に指示に忠実に従いにくくなります。中枢となる流れだけを`SKILL.md`に書き、工程を細かく分けたい場合は参考資料と同じ要領でフォルダを追加して分割し、そこから参照する形にすると、人間にとってもAIにとっても分かりやすい構造になります。

またスキルは、作って終わりではなく育てていくものです。実行結果をアウトプット用のフォルダに溜めておき、「次に実行するときは、過去の良い成果物を参考にしてから始める」という一文を指示書に加えておくだけで、使うたびに少しずつ質が上がっていく好循環を作れます。
