1

スキルって結局何なのか

「スキル、スキルってよく聞くけど結局GPTsやGemsと何が違うの」——ここが分かっていないと、この先どれだけ機能を紹介されても実感が湧きません。まずはここから。

なぜここまで注目されているのか（3つ）
1

品質の安定性

プログラムという固定処理があるので、毎回ゼロから生成し直すGPTs方式より結果がブレにくい

2

成果物のサイクルが回る

出力をアウトプット用フォルダに溜め、次回はそれを参考にしてから始める好循環を作れる

3

専門家の知見を移植できる

他の人が作ったSKILL.mdの中身を覗けば、その人の仕事の手順そのものを覗き見できる

この仕組みを使えるのは今のところClaude Code・Codex・Cursor・Antigravityなどコーディングエージェント側が中心。チャットアプリの中でスキルを扱えるのは、現状ではClaudeがほぼ唯一です。

2

Claude Code全体は何をしてくれるのか

Claude Codeは登場当初こそ「コードを生成するエージェント」でしたが、今は自分専用のAIチームを作るための土台という性格が強くなっています。ここでは土台となる3つの動かし方と、そこから働き方を広げる拡張機能という2階建てで整理します。

土台となる3つの動かし方 — この3つさえ分かれば、あとはすべて「これをもっと便利にするもの」
①

型を持ち込む
Superpowers

ベテランエンジニアの開発ワークフロー（TDDのRED-GREEN-REFACTOR、要件を詰めるブレインストーミング等）をプラグインとして持ち込める

②

知見を移植する
スキルの自作

1章の仕組みを、他人のものを探すのではなく自分の業務に合わせて作る発想。専用スキルの自作が一番価値が大きい

③

外部と繋ぐ
MCP

Slack・Notion・カレンダーなど外部サービスと繋ぐ共通規格。USBの規格のように、同じ端子で色々な機器と繋がるイメージ

そこから働き方を広げる拡張機能 — 「任せる範囲」「仕上げの質」「使える場所」の3方向に広がる
任せる範囲を広げる

Auto Mode

安全な操作はClaudeが自分で判断して進め、リスクがある操作だけ人に戻す実行モード

Routines

決まった作業をクラウド上で定期実行。PCの電源を切っても動き続けてほしい繰り返し業務向け

Agent Teams

役割ごとに複数のエージェントで「チーム」を編成し、独立したコンテキストで分担して進める

仕上げの質を上げる

Ultra Review

リモートサンドボックス上で複数レビューを並列実行し、公開前の最終チェックを担う（追加コストあり）

デザイン連携ツール
Pencil / Claude Design

専用ツールと組み合わせることで、AI感のあるデザインから抜け出しやすくする

使える場所を広げる

Remote Control

  • PCでターミナルのClaude Codeを起動したまま、外出先でスマホから残りの指示を出せる
  • AIの作業を待つだけの時間をなくせる、日常的に恩恵を感じやすい機能

研究プレビュー段階の機能を多く含むため、料金や仕様が変わる可能性がある点は留意してください。

3

今日から何を入れて、どう探すか

ここで紹介する4つは、2章で見た土台や拡張機能を、実際にインストールできる形にしたものです。

  • 1Superpowers2章の土台①そのもの。今のところ最有力候補。ブレインストーミングで要件を固め、計画・実行・レビューまでを開発経験がなくても自然になぞれる
  • 2Everything Claude Code（ECC）環境ごと整えたい人向け。エージェント・スキル・コマンド・フックを丸ごと装備。2章の内容が体に馴染んでから使うのがおすすめ
  • 3Impeccable2章の「デザイン連携」の具体例。AIが作りがちな量産型デザインを避けるための、複数の小さなスキルの束
  • 4Find Skills特定業務を助ける前3つとは毛色が違う、スキルを探す・管理するためのスキル。skills.shの`npx skills add`で直接検索・追加できる
良いスキルの安全な探し方
探し方運営・立ち位置特徴注意点
Claude Code Marketplacesコミュニティ主導の第三者ディレクトリ数千件規模。インストール数・スター順で探せる誰でも公開できる場のため中身の精査は自己責任
skills.shVercelが運営上位の多くがVercel自身・Anthropic公式・Microsoft等の企業自身の公開ターミナル操作に慣れが必要
Xでのリアルな評判検索個人ユーザーの生の声Grokのようなリアルタイム検索AIで実際に使った人の温度感を掴める定量指標ではないため参考情報として扱う

インストール数が多く、公式や有名企業が出しているものほど安心して使いやすいのが共通点。そして何より、探す前にまず自分の業務に合わせたオリジナルのスキルを自作することが、実は一番価値が大きいという点は忘れないでください。

4

今日からの使い方（初心者基準）

3つの疑問への答えが出そろったところで、「結局何からやればいいの」という人向けの対応表です。

  • 何から手をつければいいか分からない開発をしたい→Superpowersを導入して、作りたいものをそのまま伝えてブレインストーミングから始める
  • 毎回同じような許可確認でテンポが悪い→実行モードをAuto Modeに切り替えて、安全な操作は任せてしまう
  • SlackやNotion、Gmailと連携して自動化したい→使っているサービスのMCPを探してインストールし、Claude Codeから操作する
  • 決まった時間に決まった作業を繰り返したい→Routinesで、繰り返している業務を1つ定期実行に登録する
  • 作ったデザインがどこかAIっぽくなってしまう→Impeccableを入れて、`/impeccable init`から始めてみる
  • 良いスキルを探しているけど何が安全か分からない→まずskills.shで公式が出しているものを確認し、気になったらXで評判も検索する
たとえばSuperpowersを試すとき
# 難しいコマンドを覚える必要はありません
> 今、こういうことをやりたい——と自然な言葉で伝えるだけ。あとはブレインストーミングのスキルが質問を重ねながら要件を一緒に固めてくれます。
5

もう一歩進んだ使い方

2章・3章で触れた「自分の知見を移植する」を、自分で実践する段階に進んだ人向けに、フォルダ構成の考え方を紹介します。

1つのスキルフォルダの役割分担 SKILL.md — 中心となる指示書。簡潔に、全体の流れだけを書く（目安200行以内） scripts/ — 実際に実行されるプログラム（.py / .js など） reference/ — 参考にしたい資料やトンマナなど、判断材料になる情報 assets/ — 出力結果を確認するビューアーなど、補助的なファイル

指示書をすべて`SKILL.md`に詰め込むと長くなりすぎて逆に指示に忠実に従いにくくなります。中枢の流れだけを`SKILL.md`に書き、細かい工程はフォルダを追加して分割するのがコツです。

  • 実行結果をアウトプット用フォルダに溜めておく
  • 「次に実行するときは、過去の良い成果物を参考にしてから始める」と指示書に一文加える
  • 使うたびに少しずつ質が上がっていく好循環ができる
